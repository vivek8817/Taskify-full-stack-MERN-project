    Form->>Handler: onSubmit({ email, password }) or ({ name, email, password })

    Handler->>API: authAPI.login(data) or authAPI.register(data)
    API->>Express: POST /api/auth/login or /register (Axios)

    Express->>MW: cors() → express.json()
    MW->>Router: /api/auth → authRoutes
    Router->>Ctrl: registerUser() or loginUser()

    alt Register Flow
        Ctrl->>Model: UserModel.findOne({ email })
        Model->>DB: db.users.findOne()
        DB-->>Model: null (not found)
        Ctrl->>Model: new UserModel({ name, email, password })
        Model->>Bcrypt: Pre-save hook: genSalt(10) + hash()
        Bcrypt-->>Model: hashed password
        Model->>DB: db.users.insertOne()
        DB-->>Model: saved user doc
    else Login Flow
        Ctrl->>Model: UserModel.findOne({ email })
        Model->>DB: db.users.findOne()
        DB-->>Model: user document
        Ctrl->>Bcrypt: user.matchPassword(entered)
        Bcrypt-->>Ctrl: true / false
    end

    Ctrl->>JWT: generateToken(user._id)
    JWT-->>Ctrl: signed JWT (30d expiry)

    Ctrl-->>Express: res.json({ user: { id, name, email, token } })
    Express-->>API: HTTP 200/201 response
    API-->>Handler: response.data (UserPayload)

    Handler->>Ctx: login(response) — setUser()
    Ctx->>LS: localStorage.setItem("taskify_user", JSON.stringify)

    Handler->>UI: navigate("/dashboard")
    UI-->>User: Dashboard Page renders

## 3. ER Diagram — MongoDB Schema

> Current database structure (User collection only at this stage)

```mermaid
erDiagram
    USER {
        ObjectId _id PK "Auto-generated by MongoDB"
        String name "Required"
        String email UK "Required, Unique"
        String password "Required, Hashed via bcrypt"
        Date createdAt "Auto via timestamps"
        Date updatedAt "Auto via timestamps"
    }

    JWT_TOKEN {
        String token "jwt.sign(id, SECRET, 30d)"
        ObjectId userId FK "References User._id"
        Date expiresAt "30 days from creation"
    }

    USER ||--o{ JWT_TOKEN : "generates on login/register"
```

> [!NOTE]
> JWT tokens are **not stored in MongoDB**. They are stateless — generated on the fly and sent to the client. The `JWT_TOKEN` entity above represents the logical relationship, not a physical collection.

## 7. MongoDB Schema Extension — User + Task Relationship

> From Auth-only to Tasks, here's the new schema with relationships

```mermaid
erDiagram
    USER ||--o{ TASK : "owns"
    USER {
        ObjectId _id PK "Auto-generated"
        String name "Required"
        String email UK "Required, Unique"
        String password "Required, Hashed"
        Date createdAt "Auto via timestamps"
        Date updatedAt "Auto via timestamps"
    }

    TASK {
        ObjectId _id PK "Auto-generated"
        String title "Required"
        Boolean completed "Default: false"
        ObjectId user FK "References User._id (IMPORTANT!)"
        Date createdAt "Auto via timestamps"
        Date updatedAt "Auto via timestamps"
    }

    JWT_TOKEN {
        String token "jwt.sign(user._id, SECRET, 30d)"
        ObjectId userId FK "References User._id"
        Date expiresAt "30 days"
    }

    USER ||--o{ JWT_TOKEN : "generates"
```

> [!IMPORTANT]
> **User Isolation**: The `user` field in TASK schema ensures each task belongs to exactly ONE user. This is critical for data privacy — a user can ONLY see/edit/delete their own tasks.

## 9. File-by-File Implementation Guide

### 🔧 Backend Files (In Order)

#### **File 1: `backend/src/middleware/authMiddleware.ts`** 
> Route protection — verify JWT and attach user to request

**What goes here:**
- Import `jwt`, `Request`, `Response`, `NextFunction` from express
- Extend Express `Request` type to add optional `user` property
- Create `protect` middleware function that:
  - Extracts token from `Authorization: Bearer <token>`
  - Verifies JWT using `jwt.verify()`
  - Finds user in database without password
  - Attaches user to `req.user`
  - Calls `next()` if valid, returns 401 if invalid

**Dependencies needed:**
